import json
import os
import re
from collections import Counter
from pathlib import Path
import pandas as pd

ROOT = Path("..")
state = json.loads((ROOT / "refine-logs/queue/queue_state.json").read_text())
audit = json.loads((ROOT / "results/checkpoint_store/compatibility_audit.json").read_text())
manifest = json.loads((ROOT / "refine-logs/factorial_manifest.json").read_text())
status = Counter(job.get("status", "unknown") for job in state["jobs"])
manifest_jobs = [job for phase in manifest["phases"] for job in phase["jobs"]]
identities = []
for job in manifest_jobs:
    match = re.fullmatch(r"f_(\d{7})_s(\d+)", job["id"])
    assert match is not None, job["id"]
    identities.append((job["id"], match.group(1), int(match.group(2))))

manifest_seeds = sorted({seed for _, _, seed in identities})
manifest_masks = sorted({mask for _, mask, _ in identities})
assert len(identities) == 480
assert len({model_id for model_id, _, _ in identities}) == 480
assert manifest_seeds == [42, 200, 201]
assert len(manifest_masks) == 160
assert {mask[0] for mask in manifest_masks} == {"1"}
assert all({mask[position] for mask in manifest_masks} == {"0", "1"} for position in range(1, 6))
assert {mask[6] for mask in manifest_masks} == set("01234")

expected_ids = {model_id for model_id, _, _ in identities}
audit_models = [row for row in audit.get("models", []) if str(row.get("model_id")) in expected_ids]
compatible_ids = {str(row.get("model_id")) for row in audit_models if row.get("compatible")}
incompatible_ids = {str(row.get("model_id")) for row in audit_models if not row.get("compatible")}
historical_audit_rows = len(audit.get("models", [])) - len(audit_models)
state_age_hours = (pd.Timestamp.now(tz="UTC").timestamp() - (ROOT / "refine-logs/queue/queue_state.json").stat().st_mtime) / 3600
running_pids = [int(job["pid"]) for job in state["jobs"] if job.get("status") == "running" and job.get("pid")]
def pid_alive(pid):
    try: os.kill(pid, 0); return True
    except (ProcessLookupError, PermissionError): return False
live_running_pids = [pid for pid in running_pids if pid_alive(pid)]
queue_active = state_age_hours <= 1 and bool(live_running_pids)

30.2 Seven-position mask decoded

The label often shortened to “2^7” is a seven-character configuration code, not seven binary factors. The first position is fixed MSE, five positions are binary toggles, and the final position selects one of five MMD states: off plus four kernels. Consequently each seed has 2^5\times5=160 conditions.

Position Implemented role Levels Training weight / normalizer Interpretation rule
1 MSE anchor fixed at 1 1.0 / 0.18 not an estimable factor
2 Pearson correlation loss 0/1 1.7 / 1.0 binary main effect and prespecified interactions
3 first-difference L1 loss 0/1 4.1 / 0.12 binary main effect and prespecified interactions
4 Kors-vectorcardiogram angle/magnitude loss 0/1 5.0 / 1.0 binary main effect and prespecified interactions
5 empirical energy-distance loss 0/1 1.0 / 0.05 binary main effect; composite scale changes sharply
6 Goldberger limb-lead consistency loss 0/1 1.0 / 0.1 binary main effect and prespecified interactions
7 MMD state 0 off; 1–4 kernel choices 2.3 / 0.042 when active categorical with off as baseline, never a numeric dose

With the manifest-bound seeds 42, 200, and 201, the planned grid contains 480 model identities. The primary analysis must retain seed as a training-replicate block and must not treat model fits—or three seeds—as independent patient samples. Patient-level uncertainty is estimated from the test cohort; seed variability addresses optimization replication and is a different uncertainty source.

30.3 Model-level evidence contract

For each model, the final table will include:

  • full model_id, mask, seed, architecture, and observed-lead set;
  • checkpoint SHA-256, byte size, state schema, and archive locator;
  • source-bundle, environment, preprocessing, and train/validation/test content roots;
  • convergence diagnostics and prespecified exclusion status;
  • paired patient-level reconstruction, morphology, calibration, and downstream-task metrics;
  • uncertainty intervals and subgroup denominators;
  • inference recipe proving that the archived model can be materialized and loaded.

30.4 Why the previous model-by-model prose was withdrawn

The previous draft assigned clinical diagnoses such as “strictly preserves T-wave termination” from aggregate feature means in a legacy CSV. That inference was not supported. A mean QT difference cannot establish waveform-level boundary preservation; it also cannot distinguish delineator failure, pairing error, variance collapse, or checkpoint-generation mismatch. The source file lacked the identity fields needed to resolve those alternatives.

The correct diagnostic chain is:

  1. verify checkpoint and dataset identity;
  2. retain paired per-record outputs and delineation quality flags;
  3. report valid-pair denominators and failure rates;
  4. estimate paired bias, limits of agreement, robust slope, and coverage;
  5. stratify by heart rate, rhythm, morphology, sex, age, and signal quality;
  6. inspect representative waveforms under a prespecified selection rule;
  7. only then make a bounded claim about preservation.

30.5 Planned factorial analysis

For endpoint Y, a hierarchical model will estimate binary main effects, categorical kernel contrasts, prespecified interactions, seed variability, and paired patient uncertainty. The estimand is a within-architecture, within-cohort contrast—not the largest observed cell mean. Multiplicity control applies within endpoint families, while clinical non-inferiority uses prespecified margins rather than a non-significant superiority test.

The release gate requires all eligible cells, matching contract digests, no duplicate identities, no unresolved checkpoint load failures, and complete primary endpoints. Until then, this chapter is an auditable analysis specification rather than a leaderboard.
